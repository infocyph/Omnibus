# Stable release performance acceptance gate

The release gate is `.github/workflows/stable-performance.yml`, backed by `benchmarks/release-acceptance.php`. It intentionally requires a **dedicated, isolated, Linux x64 self-hosted runner labeled `omnibus-stable`** with pinned CPU allocation, PHP and operating system. Do not set `OMNIBUS_BENCHMARK_STABLE=1` on a shared GitHub-hosted runner to bypass this requirement.

The workflow runs seven balanced matched trials each of released 2.6, 2.6 with 3.0 dependencies, unbound 3.0, 3.0 host-context-only and Runwire-bound 3.0 with four real PHP accepting workers. It records the exact candidate SHA, each lockfile hash and JSON process-tree CPU/RSS, tail latency and correct-response throughput. The validator **fails** unless trials use the same stable fingerprint, labeled source revisions, zero failures/timeouts, minimum 4,000 correct requests per trial, five visible host processes and measured CPU/RSS.

Unwaived budgets: maximum 2% median successful RPM regression and trial CV; p95 +15%; p99 +20%; CPU seconds per correct operation +5%; RSS growth 4 MiB per 10k requests. The bound path is compared with current 3.0 host-only, because 2.6 has no Runwire binding. A successful shared GitHub-hosted [four-worker diagnostic](https://github.com/infocyph/Omnibus/actions/runs/37734388224) is **not** stable runner release certification. If no dedicated runner is connected, this mandatory final gate remains open; do not merge, tag or publish.

## Final validator hardening (2026-10-08)

The validator now requires exactly seven trials for each variant and validates **every** recorded workload before certifying a trial: cold request, warm HTTP at concurrency 1/2/4, expected HTTP 503 response, and the 2,000-message two-connection durable SQLite drain. It rejects missing/duplicate workloads, incomplete or timed-out requests, invalid latency percentiles, an incorrect expected-failure response, or an undrained durable queue. The output records median RPM and p50/p95/p99 for each workload. The original matched warm c4 RPM/p95/p99/CPU budgets, CV <= 2%, and RSS budget remain unchanged; cold and short/non-production workloads are reported, not misrepresented as independent statistically stable RPM certifications.

Run `php benchmarks/release-acceptance-selftest.php` to adversarially verify synthetic valid evidence, missing/duplicate workload rejection, timeouts, failed expected HTTP responses, undrained durable results, malformed latency, and an RPM regression. This self-test is automatically executed by the Batch 8 workflow on every push; synthetic data **never** counts as performance certification. First green validator-self-test run: [#37737194361](https://github.com/infocyph/Omnibus/actions/runs/37737194361).

The required stable runner remains **unassigned**: the certification job specifically requests labels `self-hosted, linux, x64, omnibus-stable`. A queued job has run no benchmark and cannot be treated as a failed or passed performance result. Provision an isolated Linux x64 runner with the last label, ensure the repository has access, and rerun for the final immutable SHA. The workflow must stay unwaived; do not move it to a hosted runner or set `OMNIBUS_BENCHMARK_STABLE=1` outside that certified environment.
